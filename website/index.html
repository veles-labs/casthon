01PREPARE YOUR MACHINE

Set up the toolchain.

The current developer preview builds from a source checkout. Install Python 3.11+, uv, Rust/Cargo, Node, Make, a C compiler, Emscripten, and Binaryen first. Then set up Casthon and let doctor check your environment.

terminal
git clone https://github.com/veles-labs/casthon.git
cd casthon
make setup
make cli
cargo install --path . --locked
casthon doctor
↳

Keep this checkout available: the preview CLI loads its compiler and SDK resources from it. See all requirements ↗

02CREATE A PROJECT

Start with Flipper.

From the checkout's parent directory, generate a small contract that stores a boolean, plus native and optional live-network tests. The project pins its compatible SDK version.

terminal
cd ..
casthon new my-flipper
cd my-flipper
uv sync
▦ Your code starts in contracts/flipper.py
03MAKE IT YOURS

Write a contract as a class.

Here is the scaffolded contract. @entry_point marks callable methods, and named_keys.property() persists the value. The exported call function installs it.

contracts/flipper.py
from casthon import ContractHash, ContractPackageHash, InvalidArgument, URef, export
from casthon.contract_api import storage
from casthon.contract_api.runtime import named_keys
from casthon.contracts import Contract, entry_point, export_contract


@export_contract
class Flipper(Contract):
    value: bool = named_keys.property()

    @entry_point
    def flip(self) -> None:
        self.value = not self.value

    @entry_point
    def get(self) -> bool:
        return self.value


installed = named_keys.reference("flipper", ContractHash)
installed_package = named_keys.reference("flipper_package", ContractPackageHash)
installed_access = named_keys.reference("flipper_access", URef[None])


@export
def call(initial: bool = False) -> None:
    if installed.name in named_keys:
        raise InvalidArgument()
    package, access = storage.create_contract_package_at_hash()
    contract, _ = package.add_contract_version(Flipper(value=initial))
    installed.set(contract)
    installed_package.set(package)
    installed_access.set(access)
↳

Edit flip or add an entry point, then update the generated tests. Explore the Python API ↗

04CHECK YOUR WORK

Test, type-check, build.

Run the scaffolded Python tests, check contract types, then compile. The build writes build/flipper.wasm; inspection shows its exports and imports.

terminal
casthon test
casthon check contracts
casthon build
casthon inspect build/flipper.wasm

05GO TO TESTNET

Preview. Then deploy.

Casthon uses the Veles Labs casper-cli for networks, wallets, signing, and deployment. Set up a testnet signer and fund it with testnet CSPR before submitting.

PREPARE A TESTNET SIGNER
terminal
cargo install casper-cli --locked
casthon doctor
casper-cli network use testnet
casper-cli wallet create mywallet
casper-cli wallet derive mywallet --start 0 --count 1
casper-cli account balance mywallet:account-0

Check that casthon doctor reports a compatible Veles casper-cli. Save the recovery phrase privately. The balance check may say “No account found” until the derived account is funded. Obtain test CSPR through Casper’s testnet funding guide ↗, transfer it to this account, then rerun the balance command.

PREVIEW, THEN SEND

The first command speculatively executes without submitting. --broadcast sends the transaction and waits for execution.

terminal
# Preview the install
casthon deploy --network testnet --from mywallet:account-0 \
  --arg initial:Bool=false

# Submit when the preview looks right
casthon deploy --network testnet --from mywallet:account-0 \
  --arg initial:Bool=false --broadcast
AFTER DEPLOYMENT

Talk to your contract.

Casthon records the executed deployment and its ABI, so the contract name is enough for a later call.

terminal
casthon call flipper get --simulate -q
casthon call flipper flip --broadcast
↳

Replace mywallet:account-0 with your configured signer. Broadcast calls submit transactions too. Read the deployment guide ↗
