02STATE + ACCESS

Counter: compose behavior.

Counter inherits Pausable, which itself inherits Ownable. It stores a U32 count and tracks increments by account in a typed dictionary. Read methods remain available while paused.

mixinstyped dictionaryowner and pause guards

The complete Counter class ↗ shows the pause guard on both increment methods and the unguarded read methods. The build exposes all inherited entry points:

from the Casthon source checkout
casthon build counter
casthon inspect build/counter.wasm

What each mixin contributes.

Counter → Pausable → Ownable → Contract is the inheritance chain. The concrete Counter class selects the Wasm exports; inherited @entry_point methods and stored fields become part of its contract. Both mixins are example modules in this repository, so copy or adapt them when building your own project.

01 / OWNERSHIP

Ownable

owner stores an account hash in a URef. On installation it defaults to get_caller(), unless the constructor receives an owner. get_owner() is public; transfer_ownership(new_owner) uses @require_owner. An unauthorized caller gets NotOwner, user error 100.

02 / PAUSE CONTROL

Pausable

paused starts as False. Only the owner can call pause() or unpause(); anyone can call is_paused(). Put @require_unpaused below @entry_point on methods that should stop while paused. A blocked call gets Paused, user error 101.

The guards are selective

Counter.increment() and increment_by() use the pause guard, so any caller can change the count while unpaused. The read methods have no pause guard. Ownership transfer changes who can pause and unpause; it does not change the paused state. A failed guard runs before the method body and leaves the count unchanged.

Try the full access-control flow.

Run this from the Casthon source checkout after installing its development environment. The session installs Counter with Alice as the default owner, tries an unauthorized pause, checks a paused write and read, then transfers ownership to Bob.

from the Casthon source checkout
.venv/bin/python - <<'PY'
from casthon import AccountHash, CLKey, CLU32
from casthon.testing import ContractHarness, MockHost
from contracts import counter
from contracts.counter import Counter
from contracts.ownable import NotOwner
from contracts.pausable import Paused

alice = AccountHash(bytes([1]) * 32)
bob = AccountHash(bytes([2]) * 32)
host = MockHost(caller=alice, strict_arguments=True)
ContractHarness(counter, host=host).invoke("call", {"initial": CLU32(3)})
contract_hash = host.accounts[alice]["py_counter"]
contract = ContractHarness(Counter, host=host, contract=contract_hash)

print("owner is Alice:", contract.invoke("get_owner").value == alice)
try:
    contract.invoke("pause", caller=bob)
except NotOwner as error:
    print("Bob cannot pause:", type(error).__name__)
contract.invoke("pause", caller=alice)
print("paused:", contract.invoke("is_paused").value)
try:
    contract.invoke("increment_by", {"amount": CLU32(4)}, caller=bob)
except Paused as error:
    print("increment blocked:", type(error).__name__)
print("count while paused:", contract.invoke("get", caller=bob).value)
contract.invoke("transfer_ownership", {"new_owner": CLKey(bob)}, caller=alice)
print("owner is Bob:", contract.invoke("get_owner").value == bob)
contract.invoke("unpause", caller=bob)
contract.invoke("increment", caller=bob)
print("count after unpause:", contract.invoke("get").value)
PY

03FUNGIBLE TOKEN

CEP-18: start with the token scaffold.

The bundled template creates a CEP-18 project using the reusable base, events, errors, and an installer. The repository's MyToken example shows the inherited contract with defaults and an upgrade path.

allowancestransferseventsupgrades
contracts/my_token.py · inherited contract excerpt
@export_contract
class MyToken(Cep18):
    def __init__(self, name: str = "My Token", symbol: str = "MYT",
                 decimals: U8 = 18,
                 total_supply: U256 = 1_000_000 * 10**18,
                 *, events_mode: EventsMode = EventsMode.CES,
                 enable_mint_burn: U8 = 1, **state: Any) -> None:
        super().__init__(name, symbol, decimals, total_supply,
                         events_mode=events_mode,
                         enable_mint_burn=enable_mint_burn, **state)

Inheriting Cep18 brings its entry points into the stored ABI. The installer creates the package and calls init; read the source before changing supply or mint permissions.

from a working directory
casthon new my-token --template cep18
cd my-token
uv sync
casthon test -- -q
from the Casthon source checkout
casthon build my_token
casthon inspect build/my_token.wasm
What to read next

Follow the CEP-18 guide ↗ for installation, permissions, events, and upgrades. The full example is my_token.py ↗.

04NFT COLLECTION

CEP-78: a complete collection.

MyNft inherits the CEP-78 base and selects defaults for metadata, mutability, owner lookup, and events. Its installer also handles upgrades. Explore it from the source checkout.

metadataownershipapprovalsreceipts
contracts/my_nft.py · collection defaults excerpt
@export_contract
class MyNft(Cep78):
    def __init__(self, collection_name: str = "My NFT",
                 collection_symbol: str = "MNFT",
                 total_token_supply: U64 = 1000, *,
                 nft_metadata_kind: NFTMetadataKind = NFTMetadataKind.NFT721,
                 metadata_mutability: MetadataMutability = MetadataMutability.MUTABLE,
                 owner_reverse_lookup_mode: OwnerReverseLookupMode = OwnerReverseLookupMode.COMPLETE,
                 events_mode: EventsMode = EventsMode.CES,
                 **state: Any) -> None:
        super().__init__(collection_name, collection_symbol,
                         total_token_supply,
                         nft_metadata_kind=nft_metadata_kind,
                         metadata_mutability=metadata_mutability,
                         owner_reverse_lookup_mode=owner_reverse_lookup_mode,
                         events_mode=events_mode, **state)

The subclass chooses collection policy; Cep78 supplies minting, transfer, metadata, and lookup behavior. Its defaults are example choices, so check them before deploying a real collection.

from the Casthon source checkout
casthon build my_nft
casthon inspect build/my_nft.wasm
