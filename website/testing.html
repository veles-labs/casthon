01PICK YOUR FEEDBACK

Use the smallest test that answers the question.

The same contract source runs at four levels. Begin with native tests while editing; add boundary, Wasm, and network coverage for behavior that depends on those layers.

01Direct Python

Logic and state, fastest feedback.

02ContractHarness

Arguments, return encoding, and rollback.

03Compiled Wasm

The frozen interpreter and host adapter.

04Local devnet

Actual Casper execution and receipts.

Where to run

The Flipper scaffold contains native and opt-in live tests. The repository checkout also has the broader compiled Wasm suite under tests/wasm/.

02FAST PYTHON TESTS

Call the class directly.

MockHost provides isolated storage and caller context. use_host binds it for the test. Your contract methods are still ordinary Python calls.

tests/test_flipper.py · direct test
from casthon.testing import MockHost, use_host
from contracts import flipper

def test_flipper_is_ordinary_python():
    with use_host(MockHost()):
        contract = flipper.Flipper(value=False)
        assert contract.get() is False
        contract.flip()
        assert contract.get() is True
from my-flipper/
casthon test -- tests/test_flipper.py -q -k ordinary_python
Boundary to remember

Direct method calls do not decode named arguments or create a transaction. Use ContractHarness for those checks.

03INVOKE THE ABI

Test the contract boundary.

ContractHarness installs the contract, encodes arguments, invokes entry points, and rolls storage back when an invocation fails. The example below is the scaffold's second native test.

tests/test_flipper.py · boundary test
from casthon import CLBool
from casthon.testing import ContractHarness, MockHost
from contracts import flipper

def test_install_and_invoke_through_the_contract_boundary():
    host = MockHost(strict_arguments=True)
    installer = ContractHarness(flipper, host=host)
    installer.invoke("call", {"initial": CLBool(True)})

    contract_hash = host.accounts[host.caller]["flipper"]
    contract = ContractHarness(flipper.Flipper, host=host, contract=contract_hash)
    assert contract.invoke("get").value is True
    contract.invoke("flip")
    assert contract.invoke("get").value is False
from my-flipper/
casthon test -- tests/test_flipper.py -q -k contract_boundary

04RUN COMPILED CODE

Exercise the actual Wasm.

The repository's compiled suite runs frozen MicroPython and the C adapter in Wasmtime. Build the example artifacts first. This suite belongs to the Casthon source checkout, rather than the small Flipper scaffold.

from the casthon source checkout
make build
casthon test --wasm -- -q
What it checks

Wasm tests cover dispatch, host signatures, returns and reverts, metering, and the compiler's lowering. They do not replace an actual Casper-network test.

05VERIFY ON CASPER

Opt in to a local devnet.

The generated Flipper live test starts an isolated network, deploys the compiled contract, flips the value, queries it, and tears the network down. Install casper-devnet and the Veles Labs casper-cli first.

from my-flipper/
casthon test --live -- -q

06SEE YOUR DEBUG OUTPUT

Print while you test. Know which build can show it.

The repository's Hello.greet prints Greeting finished in finally. This native test calls it three times: success, a caught empty-name error, and an uncaught long-name error. Each path reaches the print, even though the last invocation rolls back its state change.

from the Casthon source checkout
casthon test -- tests/test_contract_packages.py -q -k hello_installer --capture=tee-sys
How pytest shows prints

Native casthon test runs CPython. Pytest captures stdout by default and shows captured output on failure. --capture=tee-sys both displays it during the run and keeps it in failure reports. Use -s to display output without pytest capture. The Wasm build profile does not change native test printing.

DEFAULT / DEBUG WASM

Debug build

casthon build hello writes build/hello.wasm. Contract print() calls the host's casper_print; an uncaught exception also prints a traceback after finally. The Wasm harness collects these lines, and a print-capable local devnet can forward them to live tests.

DEPLOY / RELEASE WASM

Release build

casthon build hello --release writes build/release/hello.wasm without a casper_print import. casthon deploy uses release Wasm by default. Prints and dispatcher tracebacks are silent. Python still evaluates the arguments and string conversions passed to print(); returns, reverts, and finally behave the same.

Verify both Wasm profiles.

This focused test builds debug and release Wasm, invokes the same print-heavy contract in Wasmtime, and checks the captured host print buffer. Passing assertions keep the buffer out of pytest's terminal summary.

from the Casthon source checkout after make setup
casthon test --wasm -- tests/wasm/test_wasm_print.py -q -k builtin_print_formatting

For live prints, a compatible print-FD node and launcher are required. LiveNetworkTest uses debug Wasm by default, captures node lines, and attaches a bounded excerpt to failed test reports. See capture methods and limits ↗ and build profiles ↗.
